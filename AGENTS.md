# Conda

* Never rely on `conda activate`.
* Do not invoke Python interpreters or Python-installed CLI tools directly.
* Run Python-related commands through the repository-specific `conda run` command.
* Record every required dependency change in the repository's `environment.yml`.
* This repository uses the Conda environment `<env_name> = template`.

## `data/`

* `data/external/` contains source data obtained from external sources.
* `data/experiment/` contains source data collected from experiments.
* `data/simulation/` contains source data generated from simulations.
* `data/processed/` contains derived data produced by processing source data for direct use by the project.

## `docs/`

* `docs/` contains Markdown documentation for Codex project understanding.
* `docs/task/` contains task documents `task<id>_<entry_name>.md` describing task designs. After execution of corresponding task scripts in the source code area, results, analysis conclusions, and related records are appended to these documents.
* `docs/reference/` contains unprocessed reference documents used for project planning and task document preparation.

## `result/`

* `result/task<id>_<entry_name>/` contains execution artifacts generated by the corresponding task scripts in the source code area.
* `result/task<id>_<entry_name>/logs/` contains task execution logs.
* `result/task<id>_<entry_name>/metadata.yaml` records the runtime environment information of the task.
* `result/task<id>_<entry_name>/resolvedconfig.yaml` records the complete resolved configuration used for the task execution.
* `result/task<id>_<entry_name>/metrics/` contains numerical output. Structured data is stored in `<entry_name>.yaml` files, while tabular data is stored in `<entry_name>.csv` files.
* `result/task<id>_<entry_name>/figures/` contains generated figures. 

## `code/`

* The `code/` directory at the repository root contains task execution scripts and task configuration files.

* `code/task<id>_<entry_name>.py` and `code/task<id>_<entry_name>.m` are task entry scripts that invoke functional source code, while `code/task<id>_<entry_name>.yaml` declares task-specific requirements and runtime parameters.

* `code/python/pyproject.toml` manages the Python project build configuration.

* `code/python/<entry_name>/` is the Python package source directory, which is installed in editable mode.

* `code/matlab/mproject.prj` defines the MATLAB project structure, path configuration, startup environment, and project task management.

* `code/matlab/+<entry_name>/` is the MATLAB package source directory, where reusable algorithm modules and function interfaces are organized through package namespaces.

* `code/python/config/<entry_name>.yaml` and `code/matlab/config/<entry_name>.yaml` are configuration files intended for frequent reuse, while default configurations are specified in the source code.

* After task execution, the task-specific parameters, module default parameters, and runtime override parameters are consolidated into the complete effective configuration used for the execution. The generated configuration is stored under `result/task<id>_<entry_name>/`.

* `code/python/test/` and `code/matlab/test/` contain test programs. Test output are stored in `code/python/test/output/` and `code/matlab/test/output/`, respectively.

* All task scripts and test commands must be executed from `<repository root>`. Example commands are shown below:

  ```bash
  conda run -n <env_name> python code/task<id>_<entry_name>.py
  matlab -batch "run('code/task<id>_<entry_name>.m')"
  conda run -n <env_name> python -m pytest code/python/test/test_<entry_name>.py
  matlab -batch "run('code/matlab/test/test_<entry_name>.m')"

* When modifying code or performing validation tasks, Codex should prioritize the existing project test framework and development toolchain.
