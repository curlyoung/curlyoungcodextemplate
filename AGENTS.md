## `data/`

* `data/external/` contains source data obtained from external sources.
* `data/experiment/` contains source data collected from experiments.
* `data/simulation/` contains source data generated from simulations.
* `data/processed/` contains derived data produced by processing source data for direct use by the project.

## `docs/`

* `docs/` contains Markdown documentation for Codex project understanding.
* `docs/tasks/` contains task documents `task<id>_<entry_name>.md` describing task designs. After execution of corresponding task scripts in the source code area, results, analysis conclusions, and related records are appended to these documents.
* `docs/references/` contains unprocessed reference documents used for project planning and task document preparation.

## `results/`

* `results/task<id>_<entry_name>/` contains execution artifacts generated by the corresponding task scripts in the source code area.
* `results/task<id>_<entry_name>/logs/` contains task execution logs.
* `results/task<id>_<entry_name>/metadata.json` records the runtime environment information of the task.
* `results/task<id>_<entry_name>/resolved_config.yaml` records the complete resolved configuration used for the task execution.
* `results/task<id>_<entry_name>/metrics/` contains numerical outputs. Structured data is stored in `<entry_name>.json` files, while tabular data is stored in `<entry_name>.csv` files.
* `results/task<id>_<entry_name>/figures/` contains generated figures. Each figure is saved in both PNG and SVG formats.

## `code/`

* The `code/` directory at the repository root contains task execution scripts and task configuration files.

* `code/task<id>_<entry_name>.py` and `code/task<id>_<entry_name>.m` are task entry scripts that invoke functional source code, while `code/task<id>_<entry_name>.yaml` declares task-specific requirements and runtime parameters.

* `code/python/pyproject.toml` manages the Python project build configuration, project metadata, dependency environment, and development tool configurations.

* `code/python/<entry_name>/` is the Python package source directory, which is installed in editable mode.

* `code/matlab/mproject.prj` defines the MATLAB project structure, path configuration, startup environment, and project task management.

* `code/matlab/+<entry_name>/` is the MATLAB package source directory, where reusable algorithm modules and function interfaces are organized through package namespaces.

* `code/python/configs/` and `code/matlab/configs/` contain default configuration files.

* `code/python/configs/<entry_name>.yaml` and `code/matlab/configs/<entry_name>.yaml` define the default parameters of corresponding modules.

* After task execution, the task-specific parameters, module default parameters, and runtime override parameters are consolidated into the complete effective configuration used for the execution. The generated configuration is stored under `results/task<id>_<entry_name>/`.

* `code/python/tests/` and `code/matlab/tests/` contain test programs. Test outputs are stored in `code/python/tests/outputs/` and `code/matlab/tests/outputs/`, respectively.

* All task scripts and test commands must be executed from `<repository root>`. Example commands are shown below:

  ```bash
  conda run -n <env_name> python code/task<id>_<entry_name>.py
  matlab -batch "run('code/task<id>_<entry_name>.m')"
  conda run -n <env_name> python -m pytest code/python/tests/test_<entry_name>.py
  matlab -batch "run('code/matlab/tests/test_<entry_name>.m')"

* When modifying code or performing validation tasks, Codex should prioritize the existing project test framework and development toolchain.
